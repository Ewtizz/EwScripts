# EwScripts

Личные скрипты, которые ставятся на любую машину одной командой. Windows 10 и 11.

```powershell
irm https://ewtizz.github.io/EwScripts/get.ps1 | iex
```

Откроется меню — выбираете модуль, он ставится. Права администратора не нужны.

## Модули

| Модуль | Что делает |
| --- | --- |
| [NetPulse](modules/netpulse) | Монитор трафика Wi-Fi: живой дашборд в браузере, логи в CSV, разбор соединений по процессам |

## Что происходит при установке

Всё живёт в `%LOCALAPPDATA%\EwScripts` и не выходит за пределы профиля пользователя:

```
%LOCALAPPDATA%\EwScripts\
  runtime\python\          своя сборка Python, общая для всех модулей
  runtime\launch.py        запуск модуля на этой сборке
  modules\<id>\            код модуля
  modules\<id>\libs\       библиотеки модуля, если они ему нужны
  data\<id>\               данные модуля
  state.json               что установлено и какой версии
```

Python приносится свой — системный не ищется и не трогается, `PATH` не меняется.
Архив сверяется по SHA256 из [`launcher/runtime.json`](launcher/runtime.json).

Код и данные разделены намеренно: обновление заменяет `modules\<id>\`, а `data\<id>\`
остаётся нетронутым. Логи и настройки переживают апдейт.

Пункт меню «Удалить EwScripts полностью» убирает рантайм, модули и ярлыки, отдельно
спрашивая про данные.

## Обновление запущенного модуля

Работающий модуль держит свою папку занятой, поэтому лаунчер перед обновлением или
удалением проверяет, не запущен ли он, и предлагает закрыть. Отказ ничего не меняет.

Даже если папку удерживает что-то ещё, установка не пострадает: старая версия
**отодвигается переименованием**, а не удаляется. Переименование либо проходит целиком,
либо не делает ничего — в отличие от рекурсивного удаления, которое сначала стирает
содержимое и только потом добирается до самой папки, а на занятой папке оставляет
модуль без файлов.

## Как добавить свой модуль

Положить папку в `modules/` и написать в ней `module.json`:

```json
{
  "schema": 1,
  "id": "myscript",
  "name": "My Script",
  "version": "1.0.0",
  "summary": "Одна строка про то, что он делает",
  "runtime": "python",
  "entry": "run.py",
  "requires": [],
  "args": ["--log-dir", "{data}\\logs"],
  "shortcut": "My Script"
}
```

| Поле | Смысл |
| --- | --- |
| `id` | имя папок в `modules\` и `data\`; только ASCII |
| `entry` | файл, который запускается |
| `requires` | пакеты для `pip`; пустой список — pip не вызывается вовсе |
| `args` | аргументы запуска; `{data}` разворачивается в папку данных модуля |
| `shortcut` | название ярлыка в меню Пуск; без поля ярлык не создаётся |

Отдельного каталога модулей нет: лаунчер сканирует `modules/*/module.json`, так что
ничего дополнительно регистрировать не нужно. Обновление предлагается, когда `version`
в репозитории отличается от установленной — в любую сторону, поэтому откат на
предыдущую версию тоже работает.

Всё, что модуль наживает при работе, в установку не копируется: `logs`, `data`, `libs`,
`__pycache__`, `.venv`, `.git`.

## Безопасность

Команда установки скачивает и выполняет код — это та же модель, что у Microsoft
Activation Scripts, и доверять ей стоит ровно настолько, насколько вы доверяете этому
репозиторию. Перед запуском всё можно прочитать: [`docs/get.ps1`](docs/get.ps1) — 90 строк,
[`launcher/`](launcher) — сам лаунчер.

`get.ps1` намеренно написан только латиницей. Он приходит по HTTP и исполняется через
`iex`, а PowerShell 5.1 угадывает кодировку по заголовкам ответа — любой не-ASCII символ
мог бы приехать искажённым. Русский текст живёт в `launcher/*.ps1`, которые читаются с
диска как UTF-8. По той же причине файлы в `launcher/` сохранены **с UTF-8 BOM**: без него
PowerShell 5.1 читает их в системной кодировке и кириллица превращается в мусор.

## Требования

* Windows 10 (сборка 10240) или 11
* PowerShell 5.1 — есть в обеих системах из коробки
* Интернет на время установки

Менять `ExecutionPolicy` не нужно: код, пришедший через `iex`, не является файлом-скриптом
и под политику не подпадает.
