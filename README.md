# EwScripts

Личные скрипты, которые ставятся на любую машину одной командой. Windows 10 и 11.

```powershell
[Net.ServicePointManager]::SecurityProtocol=3072; irm https://ewtizz.github.io/EwScripts/get.ps1 | iex
```

Откроется меню, выбираете модуль, он ставится. Права администратора не нужны.

Первая часть команды включает TLS 1.2. Без неё PowerShell 5.1 на многих машинах
здоровается по TLS 1.0, GitHub такое соединение обрывает, и установка падает с
сообщением вроде «Базовое соединение закрыто». Сам `get.ps1` TLS тоже настраивает, но
падает как раз запрос, который его скачивает.

### Если GitHub недоступен

В некоторых сетях `github.io` не открывается: соединение обрывается на рукопожатии, и
падают одинаково что `irm`, что `curl`. Тогда ставьте с зеркала jsDelivr:

```powershell
[Net.ServicePointManager]::SecurityProtocol=3072; irm https://cdn.jsdelivr.net/gh/Ewtizz/EwScripts@main/docs/get.ps1 | iex
```

Дальше установщик справится сам: если архив репозитория не качается с GitHub, он
забирает файлы по одному через то же зеркало. Учтите, что копию ветки зеркало держит
несколько часов, поэтому свежая правка доезжает не мгновенно.

Если не работает ни то, ни другое, эта команда покажет, что именно недоступно, и ничего
не установит:

```powershell
'ewtizz.github.io','raw.githubusercontent.com','codeload.github.com','github.com','cdn.jsdelivr.net'|%{$h=$_;$t='NO';try{$c=New-Object Net.Sockets.TcpClient;if($c.ConnectAsync($h,443).Wait(5000)){$t='OK'};$c.Close()}catch{};"$h  TCP=$t  HTTP=$(curl.exe -o NUL -s -w '%{http_code}' --max-time 10 https://$h/)"}
```

`TCP=NO` — соединение до хоста не доходит, то есть блокировка в сети. `TCP=OK` с пустым
`HTTP` — обрыв на рукопожатии, а это обычно фильтрация по имени сайта.

## Что происходит при установке

Всё живёт в `%LOCALAPPDATA%\EwScripts` и не выходит за пределы профиля пользователя:

```
%LOCALAPPDATA%\EwScripts\
  runtime\python\          своя сборка Python, общая для всех модулей
  runtime\launch.py        запуск модуля на этой сборке
  modules\<id>\            код модуля
  modules\<id>\libs\       библиотеки модуля, если они ему нужны
  data\<id>\               данные модуля
  state.json               что установлено и какой версии
```

Python приносится свой: системный не ищется и не трогается, `PATH` не меняется. Архив
сверяется по SHA256 из [`launcher/runtime.json`](launcher/runtime.json).

Код и данные разделены намеренно: обновление заменяет `modules\<id>\`, а `data\<id>\`
остаётся нетронутым, так что логи и настройки переживают апдейт. Пункт меню «Удалить
EwScripts полностью» убирает рантайм, модули и ярлыки, отдельно спрашивая про данные.

Работающий модуль держит свою папку занятой, поэтому лаунчер перед обновлением предлагает
его закрыть. Но даже если папку удерживает что-то ещё, установка не пострадает: старая
версия **отодвигается переименованием**, а не удаляется. Переименование либо проходит
целиком, либо не делает ничего, тогда как рекурсивное удаление на занятой папке оставляет
модуль без файлов.

## Как добавить свой модуль

Положить папку в `modules/` и написать в ней `module.json`:

```json
{
  "schema": 1,
  "id": "myscript",
  "name": "My Script",
  "version": "1.0.0",
  "summary": "Одна строка про то, что он делает",
  "runtime": "python",
  "entry": "run.py",
  "requires": [],
  "args": ["--log-dir", "{data}\\logs"],
  "shortcut": "My Script"
}
```

| Поле | Смысл |
| --- | --- |
| `id` | имя папок в `modules\` и `data\`; только ASCII |
| `entry` | файл, который запускается |
| `requires` | пакеты для `pip`; пустой список — pip не вызывается вовсе |
| `args` | аргументы запуска; `{data}` разворачивается в папку данных модуля |
| `shortcut` | название ярлыка в меню Пуск; без поля ярлык не создаётся |
| `note` | необязательно: заметка в меню модуля и сразу после установки |
| `postInstall` | необязательно: аргументы, с которыми модуль вызывается после установки |
| `preUninstall` | необязательно: то же самое перед удалением |

`note` — для того, что важно узнать в момент установки, а не потом в README: например,
что на Windows 11 пункты контекстного меню прячутся под «Показать дополнительные
параметры». `postInstall` и `preUninstall` нужны модулям с побочными эффектами за
пределами своей папки, вроде тех же пунктов контекстного меню. Если `postInstall` упал,
установка откатывается на прежнюю версию: половинчатая установка хуже отказа, потому что
выглядит рабочей.

Регистрировать модуль отдельно не нужно, лаунчер сканирует `modules/*/module.json`.
Обновление предлагается, когда `version` в репозитории отличается от установленной, в
любую сторону, поэтому откат тоже работает. Нажитое при работе не копируется: `logs`,
`data`, `libs`, `__pycache__`, `.venv`, `.git`.

## Безопасность

Команда установки скачивает и выполняет код. Это та же модель, что у Microsoft Activation
Scripts, и доверять ей стоит ровно настолько, насколько вы доверяете этому репозиторию.
Всё можно прочитать заранее: [`docs/get.ps1`](docs/get.ps1) и [`launcher/`](launcher).

`get.ps1` намеренно написан только латиницей: он исполняется через `iex`, а PowerShell 5.1
угадывает кодировку по заголовкам ответа, так что любой не-ASCII символ мог бы приехать
искажённым. Русский текст живёт в `launcher/*.ps1`, и они по той же причине сохранены
**с UTF-8 BOM**: без него PowerShell 5.1 читает их в системной кодировке и кириллица
превращается в мусор.

## Требования

Windows 10 (сборка 10240) или 11, PowerShell 5.1 (есть в обеих системах из коробки),
интернет на время установки.

Менять `ExecutionPolicy` вручную не нужно, но не потому, что политика ни при чём. Под неё
не подпадает только сам `get.ps1`: он приходит через `iex` и файлом-скриптом не является.
А вот лаунчер, который он распаковывает, — это обычные `.ps1` на диске, и на свежей
Windows с политикой `Restricted` их импорт запрещён. Поэтому `get.ps1` первым делом
поднимает политику до `Bypass` **в области `Process`**: это действует только в текущем
окне консоли и не требует прав администратора.

Область `Process` перебивает и `CurrentUser`, и `LocalMachine`, так что ужесточённая
вручную политика установке не помешает. Не перебивает она только групповую политику
домена: такую блокировку снимает лишь администратор машины, и установщик скажет об этом
сразу, а не упадёт уже после скачивания. Если политику успели поменять руками, вернуть её
к исходной можно так:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy Undefined
```
