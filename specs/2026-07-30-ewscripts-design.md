# EwScripts — дизайн

Дата: 2026-07-30

## Цель

Система личных скриптов, которая ставится на чужую или свою машину одной командой
в PowerShell — по модели Microsoft Activation Scripts. Windows 10 и 11.
Первый модуль — NetPulse из `modules/netpulse`.

## Пользовательский сценарий

```powershell
irm https://ewtizz.github.io/EwScripts/get.ps1 | iex
```

Открывается меню:

```
  ═══════════════════════════════════════════════
     EwScripts                            v1.0.0
  ═══════════════════════════════════════════════

   [1]  NetPulse                      не установлен
        Монитор трафика Wi-Fi с веб-дашбордом

  ───────────────────────────────────────────────
   [R]  Обновить всё            [U]  Удалить всё
   [0]  Выход

   Выбор: _
```

Выбор установленного модуля открывает подменю: *Запустить / Обновить / Удалить /
Открыть папку с данными*.

Права администратора не требуются нигде — всё живёт в профиле пользователя.
`ExecutionPolicy` менять не нужно: код, пришедший через `iex`, не является
файлом-скриптом и под политику не подпадает. Язык интерфейса — русский.

## Архитектура

### Репозиторий

```
EwScripts/                       github.com/Ewtizz/EwScripts (публичный)
  docs/                          GitHub Pages, источник — /docs ветки main
    get.ps1                      то, что выполняет irm | iex
    index.html                   минимальная страница с командой установки
    .nojekyll
  launcher/
    EwScripts.psm1               меню, установка, обновление, удаление
    runtime.ps1                  скачивание и распаковка Python
    ui.ps1                       отрисовка меню
    runtime.json                 закреплённая версия Python и её SHA256
  modules/
    netpulse/
      module.json                манифест
      run.py, netpulse/, start.bat
  specs/                         проектная документация (в Pages не попадает)
  .gitignore
  README.md
```

Каталога модулей нет намеренно: лаунчер сканирует `modules/*/module.json`.
Отдельный `index.json` пришлось бы синхронизировать вручную, а рассинхрон между
индексом и файлами — это целый класс ошибок, которого можно просто не заводить.

### Раскладка на машине пользователя

```
%LOCALAPPDATA%\EwScripts\
  runtime\python\          сборка Python, общая для всех модулей
  runtime\launch.py        универсальный шим запуска
  modules\netpulse\        код модуля + module.json
  modules\netpulse\libs\   зависимости модуля (у netpulse пусто)
  data\netpulse\logs\      данные модуля
  state.json               что установлено и какой версии
```

Ключевое разделение — **код отдельно, данные отдельно**. Обновление сносит и
перекладывает `modules\<id>\`, не трогая `data\<id>\`. Логи трафика переживают
апдейт. Для этого netpulse запускается с `--log-dir`; менять его код не требуется,
ключ у него уже есть.

`state.json`:

```json
{
  "schema": 1,
  "runtime": { "kind": "nuget-python", "version": "3.12.8" },
  "modules": {
    "netpulse": { "version": "1.0.0", "installed": "2026-07-30T20:15:00+03:00" }
  }
}
```

### Доставка

Лаунчер при старте одним запросом качает zip репозитория в `%TEMP%`, распаковывает,
сканирует манифесты, показывает меню и ставит выбранное из того же архива.
Один сетевой вызов на весь сеанс; манифест и файлы гарантированно из одной ревизии.

### Манифест модуля

`modules/netpulse/module.json`:

```json
{
  "schema": 1,
  "id": "netpulse",
  "name": "NetPulse",
  "version": "1.0.0",
  "summary": "Монитор трафика Wi-Fi с веб-дашбордом",
  "runtime": "python",
  "entry": "run.py",
  "requires": [],
  "args": ["--log-dir", "{data}\\logs"],
  "shortcut": "NetPulse"
}
```

`{data}` разворачивается лаунчером в `%LOCALAPPDATA%\EwScripts\data\<id>`.
Добавить новый модуль = положить папку с манифестом. Лаунчер о конкретных модулях
ничего не знает.

Обновление доступно, когда `version` в манифесте из свежескачанного архива отличается
от записанной в `state.json`. Сравнение — на неравенство, а не «больше», чтобы откат
на предыдущую версию тоже работал. Манифест с `runtime`, отличным от `python`, лаунчер
в меню не показывает и пишет о нём в строку состояния: это модуль от более новой версии
системы.

Отвергнутая альтернатива: свой `install.ps1` в каждом модуле. Гибче, но заставляет
переписывать одну и ту же логику (скачивание, рантайм, ярлык, удаление) в каждом
новом модуле. Если однажды появится модуль с реальной спецификой — добавим
необязательный `hooks.ps1`, не ломая остальные.

### Рантайм Python

Системный Python не ищется и не трогается. При установке первого Python-модуля
качается NuGet-пакет `python` (издатель в nuspec — Python Software Foundation,
projectUrl — python.org), проверяется SHA256, содержимое `tools\` раскладывается
в `runtime\python\`.

`launcher/runtime.json`:

```json
{
  "kind": "nuget-python",
  "version": "3.12.8",
  "url": "https://www.nuget.org/api/v2/package/python/3.12.8",
  "sha256": "406856be971d957e0bee7a5cefe20a5ec78d70a495e9e33cd0e53d31faec049d",
  "size": 14465481
}
```

SHA256 обязателен: мы приносим на чужую машину исполняемый код.

### Зависимости модулей

venv не используется. Причины:

1. Рантайм и так приватный — это наша копия в `%LOCALAPPDATA%`, venv внутри неё
   изолирует от угрозы, которой нет.
2. Один общий venv развалится в тот день, когда двум модулям понадобятся разные
   версии одной библиотеки. А свободное добавление модулей — цель всей системы.
3. venv хранит внутри себя абсолютные пути и ломается при переносе папки.

Вместо него — библиотеки на модуль: если `requires` не пуст, при установке
выполняется `pip install --target modules/<id>/libs`, а `launch.py` подставляет
`libs` в `sys.path`. У каждого модуля свой набор зависимостей; удаление папки
модуля удаляет и его библиотеки. У netpulse `requires` пуст, поэтому pip при его
установке не запускается вовсе.

### Запуск модуля

`runtime\launch.py`:

```python
"""Запуск модуля на общем рантайме.

Вызов: python.exe launch.py <папка модуля> <entry> [аргументы модуля...]
"""
import os
import runpy
import sys

mod_dir = os.path.abspath(sys.argv[1])
entry = os.path.join(mod_dir, sys.argv[2])
libs = os.path.join(mod_dir, "libs")
if os.path.isdir(libs):
    sys.path.insert(0, libs)
sys.path.insert(0, mod_dir)
sys.argv = [entry, *sys.argv[3:]]
runpy.run_path(entry, run_name="__main__")
```

Лаунчер генерирует на модуль `launch.cmd`, а ярлык в
`Пуск → EwScripts → NetPulse` указывает на него:

```bat
@echo off
title NetPulse
"%LOCALAPPDATA%\EwScripts\runtime\python\python.exe" ^
  "%LOCALAPPDATA%\EwScripts\runtime\launch.py" ^
  "%LOCALAPPDATA%\EwScripts\modules\netpulse" "run.py" ^
  --log-dir "%LOCALAPPDATA%\EwScripts\data\netpulse\logs" %*
```

Консольное окно остаётся намеренно: netpulse останавливается по Ctrl+C.
Через `.cmd`, а не напрямую в ярлыке, — чтобы не воевать с экранированием кавычек
в `.lnk` и чтобы запуск можно было отладить руками.

## Проверенные факты

Дизайн опирается на эмпирику, а не на предположения. Проверено на этой машине
(Windows 11, Python 3.13 в системе) 2026-07-30:

| Проверка | Результат |
| --- | --- |
| netpulse на скачанном рантайме | работает, ctypes и Windows API отдают данные |
| `PYTHONPATH` для embeddable | **игнорируется** — мешает `._pth`, изолированный режим |
| папка скрипта в `sys.path` у embeddable | **не добавляется**, `ModuleNotFoundError` |
| обход через `runpy` + явный `sys.path.insert` | работает, рантайм остаётся нетронутым |
| `pip install --target` | работает; библиотеки импортируются нетронутым рантаймом |
| embeddable: `venv`, `ensurepip`, `pip`, `tkinter` | отсутствуют |
| embeddable: `ssl`, `ctypes`, `urllib.request` | на месте |
| NuGet-сборка: `venv`, `ensurepip`, `pip` | на месте |
| NuGet-сборка после переноса папки | работает |
| Размеры | embeddable 11.1 МБ → 21 МБ на диске; NuGet 14.5 МБ → 40 МБ |

Выбрана NuGet-сборка: на 19 МБ больше на диске, но pip уже внутри — не нужен ни
патч `._pth`, ни скачивание `get-pip.py`. Меньше шагов, которые могут сломаться
на чужой машине.

## Обработка ошибок

Внятный текст вместо стектрейса на каждом из случаев:

| Ситуация | Поведение |
| --- | --- |
| не Windows 10/11 | сообщение и выход |
| PowerShell ниже 5.1 | сообщение и выход |
| нет сети или GitHub недоступен | сообщение с адресом, который не открылся |
| SHA256 рантайма не совпал | установка прерывается, файл удаляется |
| `state.json` повреждён | пересобирается по фактическому содержимому `modules\` |
| нет места на диске | сообщение с требуемым объёмом |
| запуск от администратора | ставится в профиль запустившего, с предупреждением |

Порт дашборда netpulse обрабатывать не нужно: занятый порт он уже умеет
обходить сам, беря следующий свободный.

## Приватность и безопасность

* В `modules/netpulse/logs/` лежит около 19 МБ реального трафика: SSID, BSSID
  точки доступа, адреса, куда ходили процессы. В публичный репозиторий это попасть
  не должно. Закрыто в корневом `.gitignore` и в `modules/netpulse/.gitignore`;
  проверено `git add --dry-run` — в индекс идут 17 файлов, ни одного CSV.
* Рантайм проверяется по SHA256.
* Всё ставится в `%LOCALAPPDATA%`, права администратора не нужны.
* Репозиторий публичный — код скриптов открыт. Ничего секретного в нём нет.
* `irm | iex` требует доверия к источнику. Это осознанно принятая модель MAS;
  README объяснит, что `get.ps1` можно сначала открыть глазами.

## Что НЕ входит

Осознанно отложено, чтобы не раздувать первую версию:

* автозапуск модулей при входе в систему;
* телеметрия и сбор статистики;
* подписи и чексуммы самих модулей (рантайм — проверяется);
* не-Python модули: поле `runtime` в манифесте заложено, реализуется только
  `python`;
* автоматическое удаление рантайма при удалении последнего модуля — его убирает
  пункт «Удалить всё».

## Критерии готовности

1. `irm https://ewtizz.github.io/EwScripts/get.ps1 | iex` показывает меню.
2. Установка netpulse кладёт код, создаёт ярлык в Пуске и запускается из него;
   дашборд открывается в браузере.
3. Обновление на версию с бампнутым номером заменяет код и **не трогает**
   `data\netpulse\logs`.
4. Удаление модуля убирает код и ярлык и отдельно спрашивает про данные.
5. «Удалить всё» не оставляет ни `%LOCALAPPDATA%\EwScripts`, ни ярлыков.
6. Ветка со скачиванием рантайма проверена **принудительно** — на этой машине есть
   системный Python 3.13, и без принуждения эта ветка не выполнится ни разу.

Проверка идёт на Windows 11. Windows 10 проверить не на чем — это будет отмечено
как непроверенное, а не выдано за рабочее.

## Что выяснилось при реализации

Три вещи, которые дизайн не предвидел и которые нашлись только на запусках:

* **PowerShell 5.1 читает `.ps1` в системной кодировке, если в файле нет UTF-8 BOM.**
  Кириллица превращается в мусор, мусор ломает разбор кавычек, файл перестаёт
  парситься целиком. Файлы `launcher/` сохранены с BOM. Заодно это подтвердило
  правильность решения держать `get.ps1` чисто латинским: он приходит по HTTP, и
  BOM в нём сломал бы уже `iex`.
* **Массив с одним элементом возвращается из функции скаляром**, у которого `.Count`
  пуст. Меню сломалось бы ровно на одном модуле — то есть в текущем составе.
  Места вызова обёрнуты в `@()`.
* **`Copy-Item -Recurse` копирует всё, что лежит в папке модуля**, включая логи
  разработчика. В архиве с GitHub их нет, но полагаться на это нельзя: установка
  должна быть герметичной. Появилась `Copy-EwModuleFiles`, отсеивающая `logs`,
  `data`, `libs`, `__pycache__`, `.venv`, `.git` и `*.pyc`.

Ещё одно уточнение против первоначального дизайна: `Invoke-EwRemoveAll` не может
завершаться через `exit` — под `iex` это закрыло бы пользователю его собственное
окно PowerShell. Функция возвращает признак «закрыть меню».

## Закрытые вопросы

* **Content-Type у GitHub Pages для `.ps1`** — отдаётся `application/octet-stream`,
  но `Invoke-RestMethod` в PowerShell 5.1 всё равно возвращает `System.String`,
  и строка разбирается в scriptblock. `irm | iex` работает, откат на
  `raw.githubusercontent.com` не понадобился. Заодно это подтвердило необходимость
  держать `get.ps1` в ASCII: charset в заголовках не приходит вовсе.
* **Публичный репозиторий** — создан: `github.com/Ewtizz/EwScripts`, Pages включён
  из `/docs` ветки `main`. В опубликованном дереве 29 файлов, CSV — ноль.
* **Пустая папка `src/`** — удалить не удалось: Windows держит её как рабочую
  директорию сессии. В git её нет, на работу не влияет; убирается вручную после
  закрытия сессии.

## Не проверено

Windows 10. Всё тестирование шло на Windows 11 (сборка 26200, PowerShell 5.1).
Специфичных для 11 вызовов в коде нет, но на 10 никто не запускал — это
непроверенное, а не работающее.
